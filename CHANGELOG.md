# Changelog

Full release history for claude-harness. See `README.md` for the current-state pitch — this file is the archive.

## 6.5.0 — the mechanical layer learns to prove it is alive, and to say so when it breaks

6.4.0 fixed the four things an external audit found broken. Two of those fixes then shipped bugs of their own, each caught only by an independent reviewer. That pattern — not the individual bugs — was the actual defect: **this pack's hooks were tested by piping synthetic JSON into them, and nothing verified that a real Claude Code session invokes them the way the fixtures assume.** A parallel error-handling review found the second half of the same problem: every `catch` in every memory/gate/caveman hook emitted identical output (nothing) whether it had nothing to do or had just failed permanently, so a dead hook and a healthy idle one were indistinguishable — for as long as nobody thought to check. This release closes both gaps, adds the machinery to keep them closed on every install going forward, and — because it landed as four independently-authored PRs plus this session's own audit-response work, all branched from the same stale base with no visibility into each other — closes with a section on what reconciling all of it by hand actually found.

### Task 0 — the unverified field names, now traced on the wire

`review-gate-check.js` decides whether a review happened by reading `tool_input.skill` / `.subagent_type` / `.command`. Those names were inferred from a session's chat-facing tool schemas, never confirmed against a live `PostToolUse` payload — a reviewer said so explicitly and it shipped on secondary evidence anyway. With the transcript-scan fallback deleted in 6.4.0, wrong names would have meant a silently dead gate with no fallback at all.

Traced live via a temporary payload-dump shim inserted into the already-wired *installed* hook (no wiring change, no session restart), then reverted and re-diffed to zero. **All three field names confirmed correct** — full trace, including the payload envelope, in `audit-log/2026-08-27-task0-live-wire-trace.md`. A real `Skill(review-loop)` call flipped `reviewSeen` to `true` in live project-scope state; a real `Skill(ponytail:ponytail-help)` correctly did not. One adversarial probe came back clean and is recorded so nobody re-chases it: a **failed** dispatch (`Unknown skill: ...`) never reaches `PostToolUse` at all, so it cannot satisfy the gate — no `tool_response.success` check is needed, and adding one would be dead code.

### `onboarding/verify.js --live` — the falsifiable self-check

The old verifier had three checks, all file-presence or `settings.json` substring matching, and it reported all-green through four live broken findings. A hook can be on disk, named in `settings.json`, and still never run. New tiers:

- **`wiring`** — a real JSON parse of `settings.json` against an expected-wiring table. Catches an unwired hook (the 6.3.0 dead-hook bug), a **stale matcher** (the exact 6.4.0 upgrade bug, generalized from one hook to all of them), and an entry pointing at a hook file that no longer exists on disk. Matcher checking is token-membership, not string equality, so reordering `Edit|Write` is fine while dropping `Skill` is not. Per-group opt-in detection, so a memory-hooks-only install isn't falsely reported broken.
- **`secret-guard`** — presence, wiring, *and* a live smoke test that runs the hook against a secret literal and asserts exit 2. Distinguishes missing from present-but-unwired from present-but-neutered; all three are real failures, and the middle one is the most deceptive because the file is right there on disk.
- **`ponytail`** promoted to a **hard** tier: an unmet `required: true` claim now exits nonzero instead of reporting green — audit finding #11's exact failure mode.
- **`live`** — the tier that asks a different question: not *is it installed*, but *did it run this session*. Bootstraps this session's identity and true scope from the new scope-pin file, then looks for that session id in the state each every-turn hook writes. Reports `DEAD` for wired-present-and-still-not-executing. An absent `.caveman-active` flag counts as `DEAD`, not "not yet exercised" — that silent kill switch (finding #9) hit 6 of 20 real sessions. What it cannot prove in-session (`PreCompact`, `SessionEnd`, read-only hooks with no footprint) it labels `unprovable` rather than counting silence as success.
- **A now-unreadable `settings.json` or a failed `existsSync` says so on stderr instead of reporting `missing`** — a permissions error and an absent file are different failures needing different fixes, and a caveman config that's *present but broken* (malformed JSON, unreadable file, a typo'd `defaultMode`) is now reported as such rather than folded into "missing" — one is re-run-the-installer, the other isn't.

`install.sh` no longer carries its own embedded `node -e` matcher check; it delegates to `verify.js --check-wiring`. Both bugs previously found in that bash function were preserved as fixes rather than regressed: the settings path travels via env/argv instead of being interpolated into a JS source string (a Windows profile named `O'Brien` produced a compile-time `SyntaxError` no `try/catch` could swallow), and a genuine read/parse failure is reported loudly instead of collapsing into "not stale." A third bug was introduced and caught during this pass: `verify.js` follows the usual CLI convention (exit 0 = healthy) while the bash caller reads 0 as "stale, reprint the block", so a straight `return $rc` inverted the meaning and claimed stale wiring on a known-green install. Found by running `--check` against that green install rather than by reading the diff.

### `onboarding/test/red-demos.sh` — 14 breakages, each shown RED

The methodology point that mattered most: a checker never shown failing has not been shown working. Every claim `verify.js` makes is deliberately broken against a throwaway sandboxed install (`CLAUDE_HARNESS_TARGET` + `CLAUDE_HARNESS_HOME_OVERRIDE`, zero live mutation) and asserted to produce its specific RED — unwire a hook, roll a matcher back to `Bash`, delete a wired hook file, remove/neuter/unwire the secret guard, disable ponytail, kill the caveman flag, empty a gate's session state. Green baselines at **both** ends, so the suite cannot pass by the verifier being permanently red.

**This harness caught its own bug of exactly the class it exists to catch.** Its first version asserted by grepping the human-readable report for `"secret-guard"`, `"ponytail"`, and `"stale"` — all of which appear in a *fully green* report too (two tier names, and the prose "flagging a note stale"). Three demos would have passed no matter what `verify.js` did. Rewritten to assert against `--json` status fields, then scoped per tier after a second collision surfaced: `canary-check.js` names a row in both the `wiring` and `live` tiers, and an unscoped match silently asserted against whichever came first.

### Session scope is pinned — one session, one scope

Audit finding #5, root-caused: **a hook's `input.cwd` is the Bash tool's *persisted* cwd, not the session's launch cwd.** One `cd` inside one Bash call moved every later hook write into a different scope, splitting a single session's gate/canary/checkpoint state across two directories — where a logged MISS is effectively lost and `memory-init.js` injects the wrong scope's checkpoint next session. Fixed in `resolveScope()` alone, so all call sites inherit it: the first hook to see a `session_id` pins that session's scope in `~/.claude/session-scope.json` (global always — the one place every scope can agree to look), and every later hook reuses it. `SessionStart`'s `memory-init.js` is normally that first hook, so the pin comes from the real launch cwd. Pins prune after 30 days idle; delete an entry to re-pin.

Two deliberate limits, both tested: pinning never *creates* `<home>/.claude` (`memory-init.js` is a pure read at `SessionStart` and must leave no footprint — the suite caught this the moment the first implementation did), and an id-less payload is never pinned, since all such sessions share the literal `'unknown'` bucket and pinning it would collapse them onto one scope.

The existing suite's pinning test failed on this fix — correctly. It reused one `session_id` across three different project directories, a situation that cannot exist in reality. The fixtures were corrected to model reality rather than the fix reverted.

### `secret-guard.js` vendored — a sixth instance of the same defect, found off-inventory

`rules/security-invariants.md:5` designates `secret-guard.js` the single mechanical backstop for all of Tier 0, with no opt-out. It was **not in this repo**: it existed only as an untracked leftover at `~/.claude/hooks/secret-guard.js`, dated Jun 20, inherited from the retired v4 harness — not installed by `install.sh`, not checked by `verify.js`. Every fresh install therefore shipped the rule claiming a mechanical secret backstop and none of the hook. Structurally identical to `ponytail` being `required: true` and never installed, with strictly worse stakes.

Now at `security/hooks/secret-guard.js`, installed unconditionally (no flag — matching a rule with no opt-out), and verified functionally. Made self-contained in the process: the v4 original pulled in a shared 51-line `harness-hook-utils.js` for 12 lines of stdin-read + block, plus three functions it never used. Installed to the *same* path the existing wiring already points at, so no existing install needs to re-paste anything. Its v4 `MACHINA SECRET GUARD` message is now `CLAUDE HARNESS SECRET GUARD`, the v4 harness having been retired.

### `isGitCommitCommand` — tested against real commit strings instead of read

Both `review-gate-check.js` and `design-lane-gate-check.js` treat a commit as their trigger, so this matcher is load-bearing for two gates. It had only ever been checked against `git commit -m "x"`. Fed 16 real command shapes:

- **All 11 real commit forms already matched** — including the bash heredoc and PowerShell here-string forms this setup's own `CLAUDE.md` mandates for multi-line messages, plus `git -C <path> commit`, `--amend`, `-am`, `rtk git commit`, and `cd x; git commit`. A genuine non-finding, verified rather than assumed.
- **But `\bgit\b` matched the word anywhere**, so ordinary Bash calls that merely *name* a commit fired the gate: `cat docs/git-commit-pr.md`, or any path containing `git-commit`. That logs a MISS for a commit that never happened — the trust-eroding direction, because a gate that cries wolf gets ignored, which costs more than the gate is worth. Tightened to require `git` in command position followed by whitespace. One residual ceiling (`echo "how to git commit"`) is marked with a `ponytail:` comment naming the shell-tokenizer upgrade path rather than growing the regex.

### Checkpoint `goal` — the one claim from finding #24 that met the mechanization bar

`WORKFLOW.md`'s Understand section predicted the empty-`goal` failure in its own text; the audit then found it live (finding #2) — a real injected checkpoint with `goal:` blank and nothing but two filenames under `files:`. `memory-init.js` now nudges when the checkpoint it just injected has an empty or whitespace-only `goal:`. Folded into the existing checkpoint read rather than built as a new hook: it needs no `settings.json` wiring (an upgrade cost this pack has already made users pay twice), it reuses a read that already happens, and `SessionStart` is the one moment the agent is looking straight at the thin checkpoint while deciding what the session is about. Silent when a real goal is present — tested both ways, because a nudge that fires every session becomes noise and gets tuned out.

### Finding #24 triaged in full, and mostly *not* mechanized

All 33 "hard/always/mandatory" grep hits are triaged in `audit-log/2026-08-27-claims-backstop-triage.md` against the pre-existing bar (explicit rule ∧ real stakes ∧ zero backstop). The headline number overstates the problem: **13 of the 33 are not rules at all** — section headings, historical root-cause notes, research rejections, doc-structure prose that merely contains "always" or "never." Of the remainder: 5 already had backstops, 4 are newly backed by this release, 6 are structurally unmechanizable (self-graded — no observable distinguishes compliance from imitation, which the audit itself concluded and this triage adopts rather than papers over), 4 are judgment-only, and 1 is a deferred candidate with its reasoning recorded.

That restraint is deliberate. This pack deleted a phase-gate state machine on purpose, and mechanizing ten things to look thorough rebuilds it. The one deferred candidate (web-transport `<form method="post">` / `X-Forwarded-For`) is genuinely detectable with the same shape as an existing gate, and was still declined this pass: its false-positive surface spans docs, fixtures, and templates, and a security gate that cries wolf is worse than an honest prose rule — the same argument that motivated tightening the commit matcher above. The triage file records how to build it if it is ever picked up.

### Two claims corrected rather than propped up

- **`rules/design-lane.md:25`'s "hard gate"** ended by requiring `anti-slop`'s Delivery Gate. `anti-slop` is `required: false` and not installed, so half of a rule labelled "hard, not optional" could not execute (finding #14). Reworded so the screenshot is the hard part — it needs nothing installed — and `anti-slop` is the optional adjunct it actually is.
- **`WORKFLOW.md:49`** told the agent to "use the superpowers TDD skill." The plugin is on disk but absent from `enabledPlugins`, so `Skill(superpowers:test-driven-development)` returns `Unknown skill` (finding #13). Reworded to describe the practice without naming an unresolvable skill; TDD-when-called-for is discretionary, so naming no skill costs nothing. Enabling the plugin was the alternative and was rejected — it carries a known open Windows `SessionStart` error, which would trade a doc inaccuracy for a real per-session error.

### Failure stopped being silent — a diagnostics channel

Fail-open is kept everywhere — no hook gained a nonzero exit, none can block a prompt/Edit/Write/compaction — but the silence a failure used to disappear into is gone. Full policy in `memory/SPEC.md`'s "Failure policy" section.

- **A bounded diagnostics channel** (`recordHookError`/`readRecentHookErrors` in `_lib.js`) writes one line per failure to `~/.claude/diagnostics/hook-errors.log` — secret-stripped through the same path checkpoints use, capped at 64 KB / newest 200 lines so a hook failing on every `PostToolUse` can't grow it forever, and reentrancy-guarded so a failure inside the recorder can't recurse or escalate into a blocking error. Every hook's top-level catch now records before exiting 0, as do the inner swallows that silently skipped real work — folded into `runGateHook`'s own catch for the four gate hooks, and into `writeFlag`/`clearFlag`/`readFlag` for the caveman helpers, rather than scattered at each call site.
- **`SessionStart` reports it.** `memory-init.js` injects a count + the most recent line + the log path when anything was recorded in the last 7 days, silent otherwise — same rule as the canary and lesson-promotion nudges. Without this the log is just a file nobody opens.
- **Four latent data-loss bugs found while tracing those swallows**, each one previously invisible by construction: corrupt gate state parsed as `{}` and was then *written over*, destroying every unresolved miss with no `EXPIRED` line (now quarantined to `<file>.corrupt` and recorded); an unparseable `lastSeen` made `NaN < cutoff` false, so that session was never pruned and its open miss never expired; `appendGateLog` dropped audit lines outright when the lock was contended (now retries the append outside the lock — an append-only audit line is safer duplicated than lost); and `atomicWrite` leaked its temp file on a failed rename, under a name nothing reads or cleans up.
- **Caveman config failures are named on stderr** instead of falling through to `full` in silence: malformed JSON, an unreadable config, a typo'd `defaultMode` (`ultraa`), an unwritable/unclearable activation flag, and an unreadable `SKILL.md` are now distinguished from the expected "no config yet" state, which stays quiet.
- **The onboarding suite was passing for the wrong reason.** It sandboxed `XDG_CONFIG_HOME` for `install.sh` but not for the `verify.js` call, so the caveman assertion read the *dev machine's real* config — green here, `missing` on any clean machine. Fixed.

### Shared scaffolding — one wrapper instead of four copies

The four `PostToolUse` gate hooks (`canary-check.js`, `review-gate-check.js`, `design-lane-gate-check.js`, `visual-plan-gate-check.js`) each hand-rolled the same ~40-line lifecycle: read hook input → resolve scope/gate paths → load state → init session state → dispatch → touch `lastSeen` → prune idle sessions → atomic write → emit JSON → fail open. Extracted into `_lib.runGateHook({ gateName, defaultSessionState, ttlMs, pendingFields, describeExpired, shouldProcess, handle })`; each hook now contains only its own detection/audit logic. `memory-init.js`'s three copy-pasted index-truncation blocks (lessons, project architecture, global architecture) collapsed into one `readIndexCapped(idxPath, capBytes)`. `caveman-config.js` now owns `getFlagPath`/`readFlag`/`writeFlag`/`clearFlag`/`INDEPENDENT_MODES`, previously duplicated across `caveman-activate.js` and `caveman-mode-tracker.js`; `onboarding/verify.js` reuses `getConfigPath()` from the same module instead of its own XDG/APPDATA/home path logic. **The one behavior change hiding in a pure refactor**: `memory-compact.js`'s archive count-cap trim sorted only by `mtimeMs`, so entries written in the same second evicted in `readdir` order — nondeterministic, and the reason the same test flaked roughly 1 run in 3 on a fast disk (passing reliably on the slower Windows dev machine, flaking on Linux CI). Now tie-breaks on filename.

### Local-machine security pass

No server, DB, or dependency manifest here, so the applicable classes are local-machine ones — credential exposure, repo-controlled input turned into filesystem paths, terminal control-sequence injection. Five fixes, each with a regression test:

- **OAuth token was in `curl`'s argv** (`statusline/statusline.sh`) — `ps -o args=` is world-readable on Linux/macOS (this script itself uses `ps` on `$PPID`, so it's not theoretical), leaking the token to any other local user for the request's lifetime. Now passed via `curl --config -` on stdin instead of an `Authorization` header built into the command line.
- **Usage cache lived in shared `/tmp`** — fixed filename under a world-writable dir means a local attacker who wins the mkdir race owns it, and `>` follows a symlink they plant there (arbitrary overwrite as the user; the JSON they leave is what the statusline renders). Moved to `${XDG_CACHE_HOME:-$HOME/.cache}/claude-harness`, created `mkdir -m 700`, any symlink at the cache path unlinked before use.
- **Terminal injection via `printf "%b"`** — `%b` expands backslash escapes in values that come from outside the script (model name, `basename $cwd`, git branch, the caveman flag file); a branch named `\033[2J` repaints/clears the terminal on every prompt. All such values now go through a `sanitize_text()` that strips control characters and turns `\` into `/` (not drop — a Windows `cwd` is backslash-separated and dropping would glue path components together).
- **Note ids from repo-tracked files became filesystem paths unchecked** (`memory/hooks/_lib.js`) — `.claude/architecture/index.md` and `watch-map.json` live *inside* a cloned repo, and every consumer does `path.join(base, 'architecture', 'notes', id + '.md')`. An id of `../../../../.ssh/config` was read and injected into the agent's context by `memory-recall.js`/`memory-architecture.js`, and rewritten in place by the staleness pass — arbitrary read/write from a `git clone`. `parseArchIndexLine()` and `readWatchMap()` now drop ids failing `isSafeNoteId` (alphanumeric + `._-`, no `..`); `readWatchMap` keeps safe siblings and only drops an entry when nothing survives.
- **Redaction gaps** — `SECRET_PATTERNS` covered AWS/PEM/`ghp_` but not the credential class every machine running this pack actually holds: added `sk-ant-…`, `Bearer …`, and `token=` assignments. `canary-check.js` was the one place persisting raw assistant text verbatim (a `canary/log.md` excerpt) with no redaction at all; it now runs through `stripSecrets`.

Also: `install.sh`'s two `node -e` snippets take the settings path as `process.argv[1]` instead of interpolating it into JS source (a repo checked out under a path containing `'` broke the snippet, and worse), and CI's test workflow now declares `permissions: contents: read` explicitly.

### Test coverage: caveman + onboarding go from spot-checked to actually covered

Measuring real line coverage (`NODE_V8_COVERAGE` + `c8`) across every existing suite found two areas far behind the memory hooks' ~96%: `caveman/hooks` at 65.97% statements / 40% functions, and `onboarding/verify.js` reachable only through install-driven paths. `caveman-activate.js` — the half of the tracker that *writes* the flag — had never been executed by any suite at all.

New checks target behavior that was previously unasserted, not raw line count: `caveman-config.js`'s env-vs-file resolution order (including an *invalid* env value correctly falling through to the file rather than being honored); the tracker's write branch (level aliasing, `off` never being written as an active mode, one-shot modes suppressing the per-turn reminder); `caveman-activate.js`'s frontmatter stripping, intensity-table filtering, and survival of a malformed `settings.json`; and all four `verify.js` tiers including the `pending-manual-paste` degraded state. Both suites are now wired into `.github/workflows/test.yml`'s 3-OS matrix — previously hand-run only, so a regression in either was invisible unless someone ran it locally. **90 memory-hook checks, 38 caveman checks, 11 onboarding checks, and 14 RED demos, all green on Windows, macOS, and Linux.**

### Reconciling four independently-authored PRs into this release

This release's diagnostics/dedup/coverage/security work landed as four separate PRs, each branched from the same pre-audit base with no visibility into this session's own work or each other's. Merged by hand with `git merge-file` against each PR's actual branch (no GitHub merge, so no commit was created by the reconciliation itself), then re-verified empirically rather than by reading the diff — which is what caught the following, none of them visible from inspection alone:

- **The dedup PR's `runGateHook` wrapper dropped the pinned-scope session id**, calling `resolveScope(cwd)` instead of `resolveScope(cwd, sessionId)` — silently reopening finding #5 (the exact cross-scope split this release's own session-pinning fix exists to prevent) for all four gate hooks the wrapper drives. Fixed at the source before merging any hook onto the wrapper.
- **The diagnostics PR's own new caveman tests crashed the whole suite** — `require('$HOOKS/caveman-config')` inside a `node -e` script string used a Git-Bash POSIX path (`/c/Users/...`) embedded as literal text, which native `node.exe` cannot resolve; only argv paths get translated automatically. Routed through the suite's existing `win_path()` helper instead.
- **The coverage PR's own onboarding fixture crashed `verify.js`'s wiring tier** — a shorthand `"hooks": { "SessionStart": "caveman-activate.js" }` string-valued shape doesn't match the real array-of-command-objects `settings.json` produces, so `.filter()` on it threw. Rewritten to generate a realistic fixture.
- **Two genuine regressions surfaced only by running the merged suites**, both traced back to this session's own earlier work: the caveman config-error message lost the word "defaultMode" during merge, breaking a substring assertion; and an earlier full rewrite of `verify.js` had already dropped the word "onboarding" from its own console header, breaking a different one. Both restored.
- The dedup PR and the diagnostics PR independently made the **identical** `memory-compact.js` filename-tiebreak fix, discovering the same nondeterminism bug from two unrelated angles (a refactor pass and an error-handling audit) without either knowing the other existed.

### Deferred, explicitly — the audit's cosmetics

Logged and not fixed, called out here rather than silently dropped: the statusline's permanently-empty `$0.00/$0.00` row and its hardcoded `$` against a live `currency: GBP` (#17); the undocumented third-party `impeccable@1` `PostToolUse` hook that fires on `Write` without appearing in `settings.json` (#19); `claude-mem` installed-but-inert against its "opt-in only, never default" manifest note (#20); the `'unknown'` session bucket, unreachable through normal operation since Claude Code always supplies a `session_id` (#21); and Claude Code's own `gitStatus` probe disagreeing with `git rev-parse`, which is not this pack's code at all (#22).

## 6.4.0 — an external audit finds two dead gates and a lying manifest line

A standalone adversarial audit (fresh session, no prior context, `~/.claude/claude-harness` installed copy only) ran 27 probes against this pack's live behavior and found 4 broken items, independently re-verified against source before any fix:

- **`review-gate-check.js` was a dead gate.** It regex-matched review-tool marker words anywhere in raw transcript text — which Claude Code's own injected agent-listing boilerplate (containing `coderabbit:code-reviewer` in every session with the plugin installed) satisfied before the user typed anything, and the user's own prose mentioning "review-loop" satisfied too. Root cause: the hook was only wired on the `Bash` `PostToolUse` matcher, so it could never directly observe a `Skill`/`Agent` invocation — transcript-scanning was a workaround for that gap, not the fix. Real fix: widened the matcher to `Bash|Skill|Agent` and made detection fully structural (`tool_input.skill`/`subagent_type`/a real `coderabbit review` CLI command), same shape `design-lane-gate-check.js` already used. No transcript text is scanned anymore. 4 new tests cover both directions, including the exact two audit repro cases.
- **`caveman-mode-tracker.js` silently killed caveman mode on any mention of "stop caveman"/"normal mode"**, including inside quotes or a negated clause — hit 6/20 real local sessions, including this audit's own opening prompt (`without saying "stop caveman"`). Fixed by reusing the quote/code-span-stripping + negation-veto filter this pack's own correction-detection gate already uses (`memory/SPEC.md`, borrowed from `claude-memory-loops`) — a real "stop caveman"/"normal mode" directive still works, a quoted or negated mention no longer does. Zero test coverage existed for either caveman hook before this pass; `caveman/hooks/test/run.sh` is new.
- **`ponytail` (`required: true`) was never actually installed.** The manifest's own install note described an npm package that doesn't exist — real distribution is a Claude Code marketplace plugin, confirmed via direct README fetch. `install.sh` now runs the non-interactive `claude plugin marketplace add`/`claude plugin install` CLI subcommands itself, unconditionally (no opt-in flag, matching `required: true`), idempotent. `onboarding/verify.js` gained a real ponytail tier — the pre-existing tiers only checked file presence + settings.json wiring, which stayed all-green while this gap was live.
- **`skills/manifest.yaml`'s `version:` field was stuck at 6.2.0** through the entire 6.3.0 release — that bump's commit never touched the version line. Caught while checking installed-pack-vs-HEAD drift as part of this audit response (`install.sh --check` reported clean — file-copy drift isn't version-string drift, a distinct thing to watch for next time).
- One more audit finding (`visual-plan-local`/`onboarding` skills unresolvable via the `Skill` tool) turned out to be **already known and already the accepted resolution** — documented in `skills/manifest.yaml`'s own `known_issues` since 2026-08-25 as a Claude Code platform constraint, not fixable from within this pack. Re-verified against source rather than re-fixed.

**A second, independent review pass (the `coderabbit:code-reviewer` subagent — the CLI's review-service connection failed twice, unrelated to this repo) then found two real bugs in the fix itself, both closed same-session:**
- The caveman quote-stripping filter's naive `/'[^']*'/g` paired the apostrophes in ordinary contractions ("let's ... don't ...") as if they were a quote span and deleted a real directive sitting between them — `"let's stop caveman, and don't forget it's done"` silently failed to deactivate. Fixed with a bounded lookbehind/lookahead (`(?<![A-Za-z0-9])'...'(?![A-Za-z0-9])`) that requires a non-word character on both sides of a single-quote pair, so contractions are left alone while genuine single-quoted mentions still strip. The negation veto was also only checking the phrase's first occurrence in a prompt — a later real, unnegated occurrence after an earlier negated one would've been wrongly suppressed; now checks every occurrence. 4 more regression tests (10 total, was 7).
- **Upgrade note for existing installs:** `review-gate-check.js`'s `PostToolUse` matcher changed from `Bash` to `Bash|Skill|Agent` in this release. `install.sh`'s wiring/drift checks previously only grepped for the hook's *filename* in `settings.json`, never its matcher value — so an install still on the old matcher got no signal to update, and (worse) with the transcript-scan fallback now removed, a stale-matcher install doesn't fail safe: every commit after a real review logs a false MISS instead of the hook staying silently dead. `install.sh --check` and a plain `./install.sh --with-memory-hooks` run now both detect a stale matcher via a real JSON parse (not filename-adjacency grepping) and reprint the wiring block. **If you installed before this release, re-run `install.sh` and re-paste the updated `PostToolUse` block.**

**A Round 2 review pass (same subagent, fresh — re-reviewing the whole diff, not just the deltas) found the two Round 1 fixes above had bugs of their own, both closed same-session:**
- The bounded quote-stripping regex fixed the contraction problem but introduced the mirror-image bug: a **genuine** quoted mention that itself contains a contraction before its closing quote (`"the docs say 'stop caveman, that's how you exit' somewhere"`) failed to strip at all — the interior apostrophe aborted the whole match attempt, so the quoted phrase re-triggered deactivation. Same bug class the fix was supposed to close, different sentence shape. Fixed by letting the span explicitly swallow a `'<letter>` sequence as a contraction rather than treating every apostrophe as a boundary candidate. 2 more regression tests (12 total).
- `review_gate_matcher_stale()`'s own path handling had a second swallow-into-false-negative bug: the settings.json path was interpolated directly into the `node -e` script string, which breaks (silently, via the surrounding try/catch's `2>/dev/null`) on any path containing a literal single quote — a Windows profile named `O'Brien`, for instance. Fixed by passing the path via `process.argv` instead of string-building the script, and giving a genuine parse/read error its own exit code with a printed diagnostic, so a future failure of this kind is visible instead of quietly read as "not stale."

## 6.3.0 — the harness audits its own token spend

Two sessions building/extending this pack's own mechanical gate hooks both hit the same complaint: build cost far exceeding what the diff justified, despite two prior lessons (batch watched-file edits, scope subagent prompts) already live and applied correctly. Root cause found, not just re-flagged: both lessons cut cost *per step*; neither touches step *count*, and the newest hook of the four (`visual-plan-gate-check.js`, shipped and tested in 6.2.0's follow-on commit) had never actually been wired into `settings.json` — full authoring/test/doc cost paid, zero runtime effect, undetected because `install.sh --check` only diffed file copies.

- **`install.sh --check` now verifies hook wiring, not just file presence** — conditioned on detectable opt-in (if any hook filename appears in `settings.json`, all must). Catches exactly the dead-hook bug above.
- **All 4 gate hooks consolidated onto shared `_lib.js` scaffolding** (`gatePaths`/`readGateState`/`appendGateLog`/`writeGateState`/`pruneIdleGateSessions`) — ~200 duplicated lines removed, zero behavior change (same 71-test suite, unmodified, all green before and after). A new gate of this shape no longer hand-rolls state persistence/locking/idle-pruning from scratch.
- **Per-hook header comments trimmed** to a one-line pointer at `memory/SPEC.md` (which already carried the full rationale verbatim) — the hooks were violating this pack's own context-economy rule while documenting rules for everyone else.
- **`cost=` field added to the episodic task-log format** — a coarse per-task estimate, not instrumented telemetry, so future retros compare numbers instead of relying on how a session felt.
- **`WORKFLOW.md:44`'s plan-mode default restored its own skip clause** for trivial work — `visual-plan-local/references/plan-discipline.md` already had it; the summary bullet everyone actually reads had silently dropped it.
- **Doc quadruplication caught mid-fix, twice.** The task-log format itself was restated inline in three places (template, `WORKFLOW.md`, `memory/SPEC.md`) — one was fixed as fix #4 above, the other two only surfaced when the fix was checked with a second pass. All three now point to the template as the single source of truth instead of restating fields.
- Full audit + fix pass reviewed by a second pass before commit (not a full `/review-loop` — doc-only or 100%-test-covered-refactor changes don't warrant the CodeRabbit round-trip; noted explicitly rather than silently skipped, which is itself the proportionality argument this release is about).

## 6.2.0 — lessons stop being a store that only grows

A cross-repo memory-system review (q-agent-harness, mex-memory) checked against this pack's own `memory/SPEC.md` found a real, code-level gap: `memory-init.js`'s lessons-index truncation keeps the *first* 8000 bytes and drops the rest, so without any way to graduate a durable lesson out, new lessons eventually stop appearing in the injected `SessionStart` context while old ones squat at the front forever — the one dimension of this pack's memory layer that got worse, not better, with use.

- **[Lesson-promotion nudge](memory/SPEC.md)** — folded into `memory-init.js`'s existing lessons-index read, not a new hook file. A timestamp watermark (`<scope>/promotion/state.json`), not a repeat-count threshold: this repo's own lessons store has held exactly one lesson, ever, promoted without repeating — a borrowed "promote after 3 repeats" rule would never have fired once in its real history. `WORKFLOW.md` gets a classification-first ritual (rule vs. skill vs. architecture-note vs. leave it) in place of that rejected threshold. On promotion, the lesson's index line is actually removed — the step two prior ad hoc promotions both skipped, which is why the truncation risk above was never really closed until now.
- **Stage 1 episodic task log** — a lighter `<scope>/episodic/task-log.md` ritual (task/approach/result/lesson, no hook, no mechanical trigger). A free-standing nudge was designed and explicitly deferred: "a task ended" has no crisp boundary the way a commit or a correction does, and building a nudge around a fuzzy trigger risked becoming a fourth instance of the exact fallible-agent-judgment problem the other three gate hooks exist to catch. Stays ritual-only until Stage 1 is observed going unused.
- Went through a real `/review-loop` pass (internal + `coderabbit:code-reviewer`) before shipping — an unguarded `statSync` that could've silently dropped the *entire* `SessionStart` injection on a transient race got caught and fixed, not just the new nudge logic. 58/58 tests passing.
- **The self-learning loop turned on itself.** A token/time retro on this build's own agent-orchestration overhead produced two new global lessons — batching edits to a hook-watched file before resolving its staleness flag instead of resolving after every edit, and scoping a validation subagent's prompt to the specific open questions instead of a full independent re-derivation once a design is already read and advisor-vetted. Both are exactly the kind of lesson the promotion nudge above now watches for.

## 6.1.0 — the mechanical layer becomes a family, and it catches its own bugs

A live audit asked one question of every `required: false` entry in `skills/manifest.yaml` (52 of them): does this actually fire as default behavior, or does it just sit as well-written markdown nobody reads at the right moment? Two real gaps turned up, both closed the same way the drift canary already handled its own — an after-the-fact, non-blocking hook, not a rule that hopes to be remembered:

- **[`review-gate-check.js`](memory/hooks/review-gate-check.js)** — a commit ships with no `/review-loop`/`security-audit` evidence anywhere in the session? Logged, surfaced once on the next turn, never blocked. Prompted by a real incident: a prior session shipped exactly that.
- **[`design-lane-gate-check.js`](memory/hooks/design-lane-gate-check.js)** — a commit ships a touched UI file with no screenshot/Playwright evidence in-session? Same treatment. Detection here is almost entirely structural (`tool_name`/`file_path`, not transcript text) — a free-text scan for "done"/"verified" was designed first, then rejected, specifically because caveman-ultra's own house style uses those words constantly for unrelated work in the same session.
- **The canary caught a bug in itself.** Replaying `canary-check.js`'s own detection logic against a real transcript found it batching an entire multi-turn span into one check — one early name-drop was silently covering eight later unnamed citations. Fixed: detection now partitions on real user-turn boundaries, not hook-invocation boundaries.
- Both new hooks went through a real `/review-loop` pass on their own diff before shipping — internal review plus an actual `coderabbit:code-reviewer` pass, not skipped. Five findings, four fixed inline, one deferred with a named follow-up (`memory/SPEC.md`).
- A live diagram-design audit (skinned to this repo's own palette) produced the README's new architecture diagram, replacing several paragraphs of prose Mermaid never rendered well.
- `install.sh --with-memory-hooks` no longer reprints its settings.json wiring snippet once everything's already wired — found by re-running the onboarding flow twice against the same real machine.

See `README.md`'s "Mechanical backstops" section for the shape all three hooks share, and `skills/manifest.yaml`'s `known_issues` list for a fourth finding from the same audit that isn't a hook at all — a Claude Code platform constraint (a freshly-added skill can't be dispatched by name until a fresh session reloads the index), routed around instead of chased.
